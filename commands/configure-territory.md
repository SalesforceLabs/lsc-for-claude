# Configure LSC Territory Alignment

Interactive wizard to check and configure Territory Alignment in LSC.

## Arguments

- `check-type` (optional): Focus area - `full`, `territories`, `assignments`, `geo-rules`, `affiliation-rules`, or `territory-info` (default: full)

## Instructions

Follow these steps sequentially to validate and configure territory alignment.

### Step 1: Verify Org Connection

First, check if connected to a Salesforce org:

```
Use check_lsc_setup to verify org connection
```

If not connected, guide the user through authentication.

### Step 2: Run Comprehensive Territory Configuration Check

Run the dedicated territory configuration tool:

```
check_territory_config()
```

This queries:
- Territory2Model (active model status)
- Territory2 records (territory hierarchy)
- ObjectTerritory2Association records (explicit account assignments)
- TerrGeoAssignmentRule records (zip/brick alignment rules)
- TerrProvAffilAssignRule records (affiliation rules)
- ProviderAcctTerritoryInfo records (generated by batch jobs)

Report the summary from the tool output.

### Step 3: Check Territory Model Status

Verify Enterprise Territory Management is enabled and a model is active:

```sql
SELECT Id, Name, State FROM Territory2Model ORDER BY Name LIMIT 10
```

Report:
- Territory model names and states
- **WARN if no Active model**: Territory alignment cannot function without an Active Territory Model

### Step 4: Check Territory Hierarchy

Verify territories exist and are structured correctly:

```sql
SELECT Id, Name, Territory2Type.Name, ParentTerritory2Id
FROM Territory2
ORDER BY Name
LIMIT 100
```

Report:
- Number of territories
- Territory types present (District, Region, Territory, etc.)
- Whether hierarchy exists (parent-child relationships)
- **WARN if no territories**: Build the hierarchy before configuring alignment

### Step 5: Check Explicit Assignments

Verify accounts are assigned to territories:

```sql
SELECT Id, SobjectId, Territory2Id, Territory2.Name, AssociationType
FROM ObjectTerritory2Association
WHERE SobjectType = 'Account'
ORDER BY Territory2.Name
LIMIT 50
```

Report:
- Number of explicit assignments
- Territories with assignments
- AssociationTypes used
- **WARN if none**: Guide user to create assignments or set up geo rules

### Step 6: Check Geo Assignment Rules (if applicable)

```sql
SELECT Id, Name, Territory2Id, Territory2.Name, UsageType, GeoCode, EffectiveStartDate, EffectiveEndDate
FROM TerrGeoAssignmentRule
ORDER BY UsageType, Territory2.Name
LIMIT 50
```

Report:
- Number of zip-to-territory vs brick-to-territory rules
- How many are in effect today (no active flag — a rule applies between its EffectiveStartDate and EffectiveEndDate)
- **INFO if none**: Optional — only needed if using geo-based alignment

### Step 7: Check Affiliation Alignment Rules (if applicable)

```sql
SELECT Id, Name, Territory2Id, Territory2.Name, AccountType, AffiliationRole
FROM TerrProvAffilAssignRule
ORDER BY Territory2.Name
LIMIT 50
```

Report:
- Number of affiliation rules
- Territories and roles covered
- **INFO if none**: Optional — only needed if aligning affiliated accounts

### Step 8: Check ProviderAcctTerritoryInfo

Verify the batch jobs have been run:

```sql
SELECT Id, AccountId, Account.Name, Territory2Id, Territory2.Name,
       LastProviderVisitDate, YearToDateProviderVisitCount
FROM ProviderAcctTerritoryInfo
ORDER BY Territory2.Name, Account.Name
LIMIT 50
```

Report:
- Number of territory info records
- Territories represented
- **WARN if none but assignments exist**: Batch jobs have not been run — guide user to run them

### Step 9: Present Configuration Report

Compile findings into a summary report:

```
## Territory Alignment Configuration Report

### Overall Status: [CONFIGURED / NEEDS ATTENTION / NOT CONFIGURED]

### Territory Model
- Model name: [name]
- State: [Active / Inactive / Not Found]

### Territory Hierarchy
- Territories: [count]
- Types: [list]
- Status: [Configured / Not Found]

### Explicit Assignments
- ObjectTerritory2Association records: [count]
- Territories covered: [count]
- Status: [Configured / Not Found]

### Geo Assignment Rules
- Zip-to-territory rules: [count]
- Brick-to-territory rules: [count]
- Active rules: [count]
- Status: [Configured / Not Configured / Not Applicable]

### Affiliation Rules
- TerrProvAffilAssignRule records: [count]
- Active rules: [count]
- Status: [Configured / Not Configured / Not Applicable]

### ProviderAcctTerritoryInfo
- Records generated: [count]
- Territories represented: [count]
- Status: [Populated / Needs Batch Jobs / Not Found]

### Issues Found
1. [Issue description]
2. [Issue description]

### Recommendations
1. [Recommendation]
2. [Recommendation]
```

### Step 10: Offer Next Steps and Fix Issues

Based on findings, offer to fix issues directly using programmatic tools:

**If no Active Territory Model:**
- Guide to Setup > Territory Models
- Explain how to activate a model

**If no territories:**
- Guide to building territory hierarchy
- Explain territory types and parent-child structure
- Note: this is standard Salesforce configuration, not LSC-specific

**If no ObjectTerritory2Association records:**
- Guide to creating explicit assignments in UI or via data load
- Offer to explain geo rule setup as an alternative

**If no ProviderAcctTerritoryInfo records but assignments exist:**
- Check Admin Console territory settings: `list_admin_settings({ category: "Territory" })`
- Ask user: "Territory batch jobs need to run. Want me to check and configure the settings?"
- If yes: Use `update_admin_setting` to configure job settings
- Report what was changed

**If trigger handlers inactive:**
- Ask user: "The following trigger handlers are inactive: [list]. Want me to enable them?"
- If yes: `toggle_trigger_handler({ handlerName: "TerritoryAlignmentHandler", active: true })` for each
- Report what was enabled

**If Admin Console settings missing or misconfigured:**
- Ask user: "These settings need to be created/updated: [list]. Want me to set them up?"
- If yes: Use `create_admin_setting` or `update_admin_setting` as appropriate
- Report what was changed

**If affiliation rules exist but affiliation alignment not working:**
- Verify ProviderAffiliation records exist with matching roles
- Check that picklist values match between TerrProvAffilAssignRule and ProviderAffiliation
- Confirm parent alignment jobs completed before affiliation runs

**If batch jobs need scheduling:**
- Check Admin Console: `list_admin_settings({ category: "Territory" })`
- Ask user: "Territory batch jobs need scheduling. Want me to configure them?"
- If yes: Use `update_admin_setting` to set schedule
- Report what was changed

**If all checks pass:**
- Confirm territory alignment is properly configured
- Remind to re-run batch jobs whenever assignments or rules change
- Recommend scheduling nightly jobs for ongoing maintenance

## Example Usage

User: `/lsc:configure-territory`
> Run full territory alignment configuration check

User: `/lsc:configure-territory territories`
> Focus on territory hierarchy check

User: `/lsc:configure-territory assignments`
> Focus on explicit account-to-territory assignments

User: `/lsc:configure-territory geo-rules`
> Focus on zip/brick geo alignment rules

User: `/lsc:configure-territory affiliation-rules`
> Focus on affiliation alignment rules and picklist setup

User: `/lsc:configure-territory territory-info`
> Focus on ProviderAcctTerritoryInfo and batch job status

## Quick Validation Alternative

For a faster automated check, suggest using the audit command:

```
/lsc:audit territory-config-check
```

## Admin Console Navigation

| Task | Path |
|------|------|
| Territory Management Jobs | Admin Console > Territory Management Jobs |
| Affiliation Rules | Admin Console > Territories > Affiliation Rules |
| Territory Management Settings | Admin Console > Territory Management |

## IMPORTANT OBJECT NAME REMINDERS

- Use `Territory2` NOT `Territory__c`
- Use `ObjectTerritory2Association` NOT `AccountTerritory__c` or `TerritoryAssignment__c`
- Use `TerrGeoAssignmentRule` NOT `ZipTerritory__c` or `GeoAlignment__c`
- Use `TerrProvAffilAssignRule` NOT `AffiliationAlignmentRule__c`
- Use `ProviderAcctTerritoryInfo` NOT `TerritoryInfo__c` or `AccountTerritoryInfo__c`
- Admin Console territory job settings use Tooling API — do NOT query with run_soql
